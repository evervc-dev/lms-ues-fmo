¿Cuál es la complejidad computacional temporal del algoritmo de ordenamiento QuickSort en el peor de los casos y qué la ocasiona en la implementación estándar en C++?

// Fragmento evaluado en cátedra: Selección ingenua de pivote
int particion(int arr[], int low, int high) {
  int pivot = arr[high]; // Último elemento siempre como pivote
  /* Ciclo de particionado estructural */
}
A
O(n log n), cuando la lista ya se encuentra previamente ordenada de forma ascendente.
check
Opción Correcta: O(n²), cuando el pivote elegido es sistemáticamente el menor o mayor elemento (ej. arreglo ya ordenado en pivote final).
C
O(n), debido a la optimización de particiones simétricas en subarreglos continuos de memoria dinámica.
D
O(log n), ocasionado por la recursión pura en pilas de memoria con tail-call optimization.
psychology
Retroalimentación pedagógica para el estudiante:

En el peor escenario, cada partición genera un subarreglo vacío y otro con n - 1 elementos. La recursión alcanza una profundidad de n llamadas, totalizando n + (n-1) + ... + 1 = O(n²). Esto se resuelve seleccionando la mediana de tres o pivotes aleatorios en C++.
